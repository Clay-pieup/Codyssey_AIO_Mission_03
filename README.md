# Mission 03 · AI가 계산하는 방식을 흉내 내는 작은 계산기 (Mini NPU Simulator)
> 한 줄 요약: 숫자 표로 바꾼 그림을 필터와 곱하고 더해(MAC 연산) 십자가(Cross)인지 X인지 판정하는 파이썬 콘솔 프로그램

## 무엇을 했나
- 3×3 필터와 패턴을 직접 입력하거나(모드 1), `data.json`의 5×5·13×13·25×25 문제를 한꺼번에 채점(모드 2)한다.

- 실행 결과(data.json): 총 6개 · 통과 3 · 실패 3. 실패 3개는 두 점수 차이가 1e-9보다 작아 동점(UNDECIDED)으로 처리된 케이스 → [결과 리포트](#결과-리포트)

## 실행 방법
Python 3.8 이상, 외부 라이브러리 없음. `main.py`와 `data.json`을 같은 폴더에 둔다.
```powershell
python main.py
```
- `1` 사용자 입력(3×3) / `2` data.json 분석 / `3` 패턴 생성기(보너스: N×N Cross·X 자동 생성)

- 오류 처리 시험: `python main.py tests/data_error.json` (일부러 틀린 데이터 10개), `tests/data_broken.json` (JSON 문법 깨짐) → `2` 입력

## 구현 요약
- MAC 연산: 반복문 2개로 n×n칸을 돌며 패턴과 필터의 같은 칸끼리 곱해 더한다. 외부 라이브러리 없이 점수(float)를 돌려준다.
- 동점 처리: 두 점수 차이의 절댓값이 1e-9보다 작으면 UNDECIDED(화면에서는 '판정 불가')로 본다.
- 성능 측정: `time.perf_counter()`로 MAC 호출만 10회 재서 1회 평균(ms)을 낸다. 입출력 시간은 뺀다.
- PASS/FAIL: 판정(Cross/X/UNDECIDED)을 정규화된 expected와 비교하고, 실패 이유를 '동점'과 '반대 판정'으로 나눠 기록한다.
- 라벨 정규화: 값의 앞뒤 공백을 지우고 소문자로 바꾼 뒤 표(`+`·`cross`→Cross, `x`→X)에서 찾는다. expected와 필터 키에 같은 함수를 쓴다.
- 스키마 검증: 키에서 크기 N을 꺼내 size_N 필터를 고르고, 패턴이 N×N 숫자 표인지 검사한다. 문제가 있으면 그 케이스만 FAIL로 처리하고 계속한다.

## 결과 리포트
**1. 실패 원인 분석** — data.json 6개 중 3개 FAIL, 모두 '동점(UNDECIDED)'

| 케이스 | Cross 점수 | X 점수 | 차이 | 판정 / expected |
|---|---|---|---|---|
| size_5_1 | 0.9 | 0.8999999999999999 | 약 1e-16 | UNDECIDED / X |
| size_13_2 | 7.499999999999997 | 7.5 | 약 3e-15 | UNDECIDED / Cross |
| size_25_1 | 4.9 | 4.899999999999999 | 약 2e-15 | UNDECIDED / X |

- 데이터·스키마 문제도, 로직 문제도 아니다. 키·크기·라벨 검증을 모두 통과했고, 같은 MAC·판정 코드로 나머지 3개와 [오류 시험](#실행-방법)의 정상 케이스는 PASS했다.
- 수치 비교 문제다. 필터 가중치가 두 점수를 거의 같게 만들고(예: size_5_1은 X 필터 0.1×9칸 = Cross 필터 가운데 0.9), 컴퓨터가 0.1 같은 소수를 정확히 저장하지 못해 1e-15 정도의 오차가 남았다.
- `==`로 비교했다면 이 오차만으로 승패가 갈린다(세 케이스 모두 expected와 반대쪽). epsilon(1e-9) 비교는 이것을 '사실상 같은 점수'로 드러낸다.
- 데이터나 epsilon을 바꿔 PASS로 만들지 않았다. 이 패턴들은 주어진 필터로는 구분되지 않는 경우이고, 정답에 맞춰 기준을 바꾸면 다른 데이터의 잘못된 판정을 숨기게 된다.

**2. 시간 복잡도 분석** — O(N²)

| 크기 | 연산 횟수(N²) | 평균 시간(ms, 10회) |
|---|---|---|
| 3×3 | 9 | 0.0014 |
| 5×5 | 25 | 0.0022 |
| 13×13 | 169 | 0.0101 |
| 25×25 | 625 | 0.0253 |

- 코드 근거: `mac()`은 반복문 두 개가 겹쳐 안쪽 곱셈·덧셈이 정확히 N×N번 실행된다.
- 측정 근거: 크기가 커질수록 시간이 칸 수를 따라 늘었다. 13×13→25×25에서 연산 3.7배, 시간 2.5배.
- 작은 크기에서는 함수 호출·시간 측정 같은 고정 비용 비중이 커서 배수가 덜 나온다(3×3→25×25: 연산 69배, 시간 18배). 한 번은 3×3이 5×5보다 느리게 측정되기도 했다.
- 의미: 한 변이 2배면 계산은 4배다. 실제 AI는 수백×수백 필터를 수천 개 쓰므로, 한 번에 하나씩 계산하는 CPU 대신 동시에 많이 계산하는 NPU가 필요하다.
